# Task 053: Web report on Tailwind CSS 4, tips card and better charts

- **Branch**: `feature/053-report-tailwind-charts-v2`
- **Implementer**: Antigravity
- **Related ADRs**: ADR-0018 (Thymeleaf SSR, zero JS, CSP, `th:text` only). This task needs a **new ADR-0020** (Tailwind as a build-time CSS tool; amends ADR-0018 on tooling only). Do not edit ADR-0018 or any other existing ADR.
- **Depends on**: 049 merged (current report page, five SVG charts) and 048 (stored `input_json`). Runs in parallel with task 052; see "Parallel work with 052".

## Goal
Rebuild the look of the public report page (`/r/{publicId}`) with Tailwind CSS 4, add a "Top Tips" card, and make the SVG charts clearer and more consistent with the page theme. The backend keeps sending data into server-rendered HTML; no JavaScript, no SPA, no runtime Node.

## Architecture decision (answer to "does the backend send the data and Tailwind builds it?")
- **Unchanged**: Spring MVC loads the report data (`ReportService`), puts it in the model, Thymeleaf renders the HTML. Charts are generated in Java as SVG and served by `ReportController`.
- **New**: Tailwind only replaces the hand-written `report.css`. A build step turns the Tailwind source plus the class names found in the templates into one minified `static/report.css`.
- **Tooling choice (recommended, implement this)**: Tailwind CSS v4 **standalone CLI** (a single binary, no Node, no npm). The generated `src/main/resources/static/report.css` is **committed**, so `./mvnw verify` and the Docker build need no extra tool and ADR-0018's "no frontend build step in `verify`" still holds. A script regenerates it; CI checks it is up to date.
- **Rejected options** (put them in ADR-0020 with pros and cons): (a) Maven plugin that downloads Node/Tailwind during the build: slower build, ARM64 and offline problems in Docker, more moving parts; (b) CDN Tailwind: breaks the CSP (`default-src 'none'`) and ADR-0018; (c) React/Vue SPA with a JSON API: new toolchain, CORS, duplicate DTOs, against ADR-0012/0018.
- **Charts stay as SVG `<img>` endpoints.** Inline SVG would need `th:utext` (banned by ADR-0018) and a looser CSP. Mention inline SVG as a possible future option in ADR-0020. The SVG files already carry their own light/dark styling (`prefers-color-scheme` inside the SVG); this task keeps that approach.

## Why (verified in the repo)
- `report.html` (220 lines) and `static/report.css` (614 lines, hand-written, CSS variables, `prefers-color-scheme`, print block) exist. Charts are `<img th:src="@{/r/{id}/....svg}">` for `soul-lead`, `soul-curve`, `phases`, `deaths`, `metrics`; plus `/chart.png`.
- `ReportController` sets this exact CSP: `default-src 'none'; img-src 'self'; style-src 'self'; base-uri 'none'; frame-ancestors 'none'`. Also `X-Robots-Tag`, `Referrer-Policy`, `X-Content-Type-Options`, `Cache-Control: private, max-age=300`. None of these may change.
- `ReportView` is a record with `AnalysisResult analysis`, `build`, `metricsTable`, `coachSections`, `otherSignals`, chart booleans and alt strings. `ReportService` already parses `result_json` and `input_json` (Jackson tree).
- The server runs on Oracle ARM64; the dev machine is Linux x64. The CLI has release assets for both.
- `pom.xml` has only `spring-boot-maven-plugin` as a plugin. Dockerfile builds with `./mvnw package` only.

## Behavior

### Tailwind rules
- Tailwind v4 CSS-first config (no `tailwind.config.js`). Dark mode uses the default media-query variant (`dark:`), matching today's `prefers-color-scheme`. Support `print:` utilities (hide decoration, keep all text).
- **Class names must appear as complete literal strings** in the template or Java source; Tailwind cannot see names built with string concatenation. For conditional styling (win/loss, severity `minor|notable|major`, verdict colors) use `th:classappend` with a ternary that contains the full class names, or a lookup in Java that returns full names. Add a test that every severity and verdict value maps to a complete class name.
- Theme tokens in `@theme` (must keep the shared meaning from tasks 047/049): gold = you (`#e5a93c`), grey = reference/teammates, blue = your team / strength (`#4c9be8`), orange = leak / enemy (`#f28c28`), green and red only for better/worse verdicts and always with a text label. Chart colors in Java must use the same hex values from one constants class, with a comment pointing to the theme.
- System font stack only. No external fonts, images, scripts or CDN. Generated CSS should stay small (target under 40 KB minified; report the size).

### Page (mobile first, readable at 360 px, single column under 720 px)
1. Hero banner: hero, result badge, rank, duration, match id, date (as today, restyled).
2. Verdict strip: leak (with severity color and label), next-game action, strength.
3. **Top Tips card** (new): ordered list of up to 3 tips; each shows the tip, then "Evidence" and "Drill" lines. Source: the `tips` array inside the stored `result_json` (items `tip`, `evidence`, `drill`; written by task 052). Read it in `ReportService` from the JSON tree (`ReportView.tips`, a `List<Tip(String tip, String evidence, String drill)>`), not through `AnalysisResult`, because 052 is not merged in this branch. Missing, empty or malformed `tips` means no card and no error. Cap 3, ignore items with a blank `tip`.
4. Key numbers with bars (existing `widthClass` logic; keep the fixed `w0..w100` mapping, but as Tailwind-safe full class names or `w-[..%]` forms that exist as literals; no inline `style=`).
5. Charts block, then collapsible `<details>` detail sections (first open), final build, footer with the donation text if present (keep the existing donation model attribute behavior from task 050).
6. Print stylesheet via `print:` utilities.

### Charts
Goal: each chart is understood in 5 seconds without reading the page text.
1. **Shared look** for all SVGs: same palette constants, same font sizes (no text under 12 px at the rendered 360 px width: choose `viewBox` and font sizes accordingly), light and dark styling inside the SVG, light gridlines with unit labels (`k` souls, `min`), a title-free canvas (the HTML card holds the title), safe margins so labels never clip.
2. **Direct labels instead of legends** where possible (label the line end: "You", "Teammates", "+6% vs average").
3. **Soul lead**: shaded ahead/behind areas, zero line, the biggest swing annotated, phase bands. **Soul curve**: keep, add the end verdict. **Phases / Deaths / Metrics**: keep their data and fallbacks from 049; improve spacing, labels and color use per the shared look. Metrics chart: show verdict text next to each bar (never color alone).
4. **New: Build timeline** (`GET /r/{publicId}/build.svg`, `ReportView.hasBuildTimeline`): a horizontal match-minute axis with one tick per purchased item (from `ReportView.build`, which has the buy minute) and its name above or below the tick, alternating rows to avoid overlap; at most 12 items (earliest first), omit the chart when there are fewer than 3 items or no buy minutes. Add title/caption/alt keys like the other charts.
5. Escape every dynamic string in SVG (hero, item names). Endpoints keep validation, headers and 404 behavior; `serveSvg` is reused.
6. Do not add per-death times or any new stored data.
