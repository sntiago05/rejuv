# Task 055: Match scoreboard, readable charts, readable analysis format and a Deadlock-style Tailwind report

- **Branch**: `feature/055-report-scoreboard-readability`
- **Implementer**: Claude Code
- **Related ADRs**: ADR-0018 (Thymeleaf SSR, zero JS, strict CSP, `th:text` only), ADR-0020 (Tailwind at build time), ADR-0019
- **Runs in parallel with**: 056 (`/draft`, `/synergy`) and 057 (`/trends`, `/nemesis`, rank percentile). No shared code except `messages.properties` (append at the end).

## Goal
1. Add a **match scoreboard** to the web report: all players of the match in two teams, like third-party trackers (hero, name, K/D/A, KDA, creeps, damage, final items), with the viewer highlighted.
2. Make all report **charts more legible** (bigger text, clearer marks, one plain-language takeaway per chart).
3. Make the **analysis text readable and accessible** in the web report and in the Discord `/analyze` embed (short scannable blocks, clear order, no wall of text, no information by color alone).
4. Restyle the web report with Tailwind so it feels closer to the look of the game Deadlock (dark noir with gold and amber accents), using references found by search. No copied game assets.

## Verified facts
- `MatchTelemetry(matchId, durationS, players, averageBadge, midBoss)` holds all players (`PlayerTelemetry(accountId, team, heroId, items, snapshots, ..., playerSlot, ...)`). The last `StatSnapshot` gives `netWorth`, `playerDamage` and `SnapshotDetail(kills, deaths, assists, creepKills, denies, ...)` (cumulative). `ItemPurchase(itemId, boughtAtS, soldAtS)`: an item with `soldAtS != null` is not a final item.
- `ReportService.find` already loads telemetry through `matchMetadataSource.getMatch` (cached 24 h) and degrades without it. `GameAssets.heroNames()`, `itemsById()`; `HeroAsset` has `images` (`icon_image_small`, `icon_hero_card`), `ItemAsset.image` is a URL.
- Report CSP is `default-src 'none'; img-src 'self'; style-src 'self'; base-uri 'none'; frame-ancestors 'none'` and must **not** change. External icon URLs therefore cannot be used directly in `<img>`: icons must be served by our own endpoints.
- Winner is not in `MatchTelemetry`. The viewer's result (`ReportView.result`) plus the viewer's team gives the winning team; when the result is unknown, show neutral team labels.
- Per-player names are not stored. Names use the same best-effort Steam persona lookup as `/mates` (`Player #accountId` fallback, sanitized text).

## Behavior
1. **Scoreboard.** Two team cards, the viewer's team first. Header: label ("Your team" / "Enemy team"), outcome (Victory/Defeat only if known), team kills and net worth. Row: hero icon + hero name, player name (viewer row marked "You" in text, not only by color), K/D/A, KDA ratio `(K+A)/max(1,D)` with one decimal, creeps, damage with a bar class `w0..w100` relative to the best damage in the match, final items as icons with the item name in `alt`. Rows are in a real `<table>` (with `<caption class="sr-only">`, `<th scope>`) on wide screens and stack as cards below 640 px; no horizontal scroll at 360 px. A match with no telemetry shows no scoreboard and no error. Do not invent grades (S/A/B) or kill participation labels not defined here.
2. **Charts.** All SVG text at least 14 px at 360 px width, strokes at least 2.5 px, a high-contrast palette checked in light and dark, direct labels instead of legends where possible, minute and k units on axes, no overlapping labels (cap and thin ticks), and a one-sentence takeaway rendered above each chart in the page from existing `alt` strings or new keys. Keep the existing endpoints, ids and security headers. Verdict is always text plus symbol, never color alone.
3. **Analysis format in the web report.** Order: verdict banner, "Biggest leak" and "Next game" cards first, then Top Tips, scoreboard, charts, details. Body text at least 16 px, line length at most about 70 characters, one idea per paragraph, headings in order (single `h1`), landmarks (`header`, `main`, `footer`), a skip link, visible focus rings, `prefers-reduced-motion`, contrast at least WCAG AA (4.5:1 text), native `<details>` kept, language attribute set, print styles kept.
4. **Look.** Before styling, search the web for references (screenshots and descriptions of the Deadlock UI, the Deadlock website, community trackers, art-deco and noir game UI palettes) and write what was used in `docs/references/deadlock-style-notes.md` (URLs and the decisions taken). Use only own CSS: dark charcoal and teal-black backgrounds, brass/gold and amber accents, red for danger, subtle borders and angular or beveled panel corners, tracking-wide uppercase headings. No game art, logos or fonts; no external fonts or CDNs (CSP). Palette tokens stay the shared ones for charts.
5. **Discord embed.** Keep the field order of ADR/047 but make it scannable: a one-line verdict in the description; each field at most 3 short lines or bullets; bold lead word per bullet; the key-numbers table is replaced by lines like `Souls/min 612 (peers 540) ▲` that wrap on mobile (no wide monospace table); keep Top Tips (task 052); keep limits (field 1024, embed 6000, 25 fields) and the donation field rules. Footer and button behavior unchanged.
6. **Safety.** Every dynamic string goes through `th:text`; player names are sanitized; the icon endpoints accept only ids present in the match.
7. **Performance.** One telemetry load per page view (already cached); no per-row network calls except one batched persona lookup and cached icon fetches.
