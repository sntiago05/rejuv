Single source of truth for project state. Compact snapshot, not a log: per-task detail lives in `docs/task-reports/NNN-*.md`, the specs in `docs/tasks/`, decisions in `docs/adr/`. Legend: **Done** = merged and verified in the repo. **Planned** = decided or specified, not built.

## Who
Backend student (Spring Boot, Riwi Colombia), intermediate level, 15-30 h/week, budget under 100,000 COP. Plays Deadlock and LoL. Goals: online income, portfolio, learn AI-assisted development. Explain important decisions; chat explanations in Spanish; everything produced (code, docs, commits, bot UI) in English.

## Product
Rejuv: English-language Discord bot that coaches Deadlock players with AI analysis of their matches. Differentiator vs stats sites (Deadlock Assistant has 600+ servers but no AI coaching): specific, personal, actionable advice plus social server features. Built i18n-ready.
- Commands implemented: `/ping` (dev guild), `/help`, `/link`, `/unlink`, `/profile`, `/analyze`, `/matches`, `/donate`, `/meta`, `/build`, `/counter`, `/heroes`, `/mates`, `/leaderboard server`, `/items` and `/compare` (open to everyone since 051; `/usage` was removed). Behavior spec: `docs/mvp-spec.md`; feature catalog: `docs/features.md` (ADR-0014).
- `/analyze` = a match vs p25/p50/p75 of the same hero and rank tier; Haiku returns strict JSON (strength, biggest leak, next-game action, key numbers). Free for everyone, no usage limits and no premium tier since 051 (ADR-0019); support comes from an optional donation link set by `DONATION_URL`/`DONATION_LABEL` (050).
- Surfaces: Discord bot first; public web report per analysis (ADR-0012, ADR-0018).
- Costs: initial ~20,000 COP; ~2 COP per analysis; details in `docs/costs.md`.

## Stack and architecture
Java 21, Spring Boot 4.1, JDA 5.6, Maven, PostgreSQL 17 + Spring Data JPA + Flyway, Caffeine, Spring `RestClient`, Spring MVC + Thymeleaf (web report), Claude Haiku 5.5 `claude-haiku-5-5`, Docker Compose (Oracle Cloud ARM64). ADRs 0001-0019.
Packages (`sntiago05.rejuv`): `commands` (no logic) -> `services` -> `clients` (cached external APIs) / `repositories`; plus `domain`, `config`, `web`.
`/analyze`: deferReply -> select match (history, cached) -> stored analysis? return it -> metadata + benchmarks + item stats -> `CoachContextService` providers -> Haiku -> store -> embed with build field, PNG chart and optional "View full report" button.

### Key facts per area (what future tasks must know)
- **Telemetry model:** `MatchTelemetry`/`PlayerTelemetry` (own model, not API DTOs). Since 029 players carry `playerSlot`, `assignedLane`, `deaths` (`DeathEvent`: time, killer slot, respawn seconds) and each `StatSnapshot` has an optional `SnapshotDetail` (kills/deaths/assists, creep kills, possible creeps, shots hit/missed, denies, damage taken, lane/neutral gold, gold lost on death). **Only the JSON adapter fills them** (it also fills `MatchTelemetry.averageBadge`, the mean of the non-zero team average badges, since 018); the raw fallback leaves `detail`, slot and lane `null` and no deaths, so consumers must treat that as "no data".
- **Coach extension point (029):** implement `CoachInsightProvider` (`key()`, `provide(CoachRequest)`) as a `@Component`; `CoachContextService` runs providers sequentially in key order, isolates failures, and the result goes to `AnalysisInput.coach` (omitted from the JSON when empty). Runs only on the fresh-AI path. Registered providers (keys): `phases` (031: z-scores at 6/12/20/30 min, phase changes), `deaths` (032), `build` (033: calls `BuildService` once, needs a rank tier), `recent_form` (034: only match and history, works in degraded mode), `matchup` (035: needs `assignedLane` for the lane part; pair win rates are global and correlational). Each payload is under 1,200 characters with `significance` none/notable/major; shared rules in `docs/coach-provider-rules.md`. Since 037 the prompt (`prompts/analysis-system.txt`, ~2.9k chars) explains these keys and tells the model to pick `biggest_leak` from the entry with the highest `significance` (tie order deaths, phases, build, matchup, recent_form) and to return `focus_area` and `severity`.
- **Performance curve:** `DeadlockApiClient.getPerformanceCurve(heroId, rankTier)` -> `PerformanceCurvePoint` list (time in seconds from `resolution=0`; `_avg` and `_std` of net worth, kills, deaths, assists, player damage, denies, creep kills), cache `deadlockPerformanceCurve` 6 h/500. Only mean and std exist (no percentiles).
- **Player item stats (021):** the endpoint is `GET /v1/analytics/item-stats` with `account_id`, `hero_ids`, `min_unix_timestamp` (there is no `/v1/players/{id}/item-stats`). Cache `deadlockPlayerItemStats` 10 min/200.
- **Free model (051, ADR-0019):** no usage limits, no premium tier, no Patreon code, no `/usage`. `PremiumFeatureGate`, `UsageService`, the role gateway and their config (`rejuv.usage.*`, `rejuv.premium.*`) are deleted; `analysis_usage` is dropped by V6 (its counts are gone for good). `/items` and `/compare` need only a linked account. `AnalyzeService.analyze(discordUserId, ...)` still takes `discordUserId` but no longer uses it (follow-up). The `GUILD_MEMBERS` intent stays (needed by `/leaderboard server`).
- **Donations (050):** `DonationProperties` (`rejuv.donation.url|label`, env `DONATION_URL`, `DONATION_LABEL`; both passed in `compose.prod.yaml`) -> `DonationService.get()` returns `Optional<Donation>`, empty unless the URL is non-blank, has no whitespace, is at most 512 chars and is `http(s)` with a host (one WARN at startup if invalid; label trimmed, default `Support Rejuv`, cut to 80). The link shows in `/donate` (ephemeral embed + link button; plain text when off), `/help` (last line), the `/analyze` embed (last field, skipped if the embed would pass 6000 chars or 25 fields) and the report footer (`DonationModelAdvice` adds model attribute `donation`; `rel="noopener noreferrer nofollow"`). No link means no donation text anywhere. Default is empty: no fake link ships.
- **Web (017):** `rejuv.web.base-url` (`WEB_BASE_URL`, blank = no button), server binds `127.0.0.1:${WEB_PORT:8080}` by default, page headers set `noindex` and a strict CSP, no JavaScript. Page shows analysis text, final build and the PNG chart; `rank`/`result` are not stored. Since 018 the page also shows the soul curve as a server-side SVG (absent when metadata, lobby badge or curve are missing). HTTPS: optional Caddy service under compose profile `https` (`Caddyfile`, `DOMAIN` env, bot binds `0.0.0.0` in `compose.prod.yaml`); not run on a real server or domain yet. Layout and charts since 049: see "Report page (049)".
- **Metadata fallback (023):** `FallbackMatchMetadataSource` (`@Primary`) tries JSON then raw (Zstandard + hand-written protobuf reader) on 503/429/I-O/invalid body; 404 never falls back. Real payload is Zstandard although the OpenAPI text says bz2. Needs a glibc base image for `zstd-jni`.
- **Presentation convention (every embed command):** `EmbedStyle.COLOR`, hero/item names through `IconCatalog` + `EmbedStyle.withIcon`, thumbnail via `AssetImages`, every field through `EmbedStyle.fitField`, must work text-only (mandatory test).
- **`/compare` (038):** `CompareService` (sample: hero filter, matches of 10+ min, newest 20, minimum 5), benchmarks at fixed tier 11 plus the player's own rank median (tier 1-10 only); deaths is lower-is-better. No telemetry (skips items and damage per minute on purpose).
- **Analysis result (037):** `AnalysisResult` has nullable `focusArea` (phases, deaths, build, recent_form, matchup, metrics) and `severity` (minor, notable, major); invalid values normalize to `null` without failing the analysis; old stored JSON still parses. Embed and web prefix the leak with `analyze.severity.*` when present. `focus_area` is stored but not shown. `max-tokens` stays 1500.
- **Soul curve rank (037):** with a lobby average badge the curve uses it; when it is missing (non-ranked match) `ReportService` uses the player's current rank from `getPlayerRank` (caption `report.curve.caption_own_rank`); unranked player means no curve.
- **Caches (040):** `CacheConfig` registers 19 Caffeine caches with `recordStats()` and `@EnableCaching(proxyTargetClass = true)`. TTLs: assets 2 h; benchmarks, item stats, hero stats, item flow, ability order, hero counters, counter items, performance curve 3 h; match metadata 24 h (size 1000, on `JsonMatchMetadataSource`); `deadlockMatchMetadataRaw` 2 min (on `RawMatchMetadataSource`; `FallbackMatchMetadataSource` has no cache); match history 45 s; rank, ranks, profile summary, player hero/mate/item stats 5 min; names 1 h. `LinkService` evicts profile, history and rank on link/unlink.
- **Degraded analyses (040):** if telemetry is unavailable and the AI answers, the report has no `publicId`, is not stored; analyses from raw fallback telemetry are still stored. Coach entries with `significance` none are omitted; `p75` is no longer sent.
- **gzip (042):** `GzipInterceptor` sends `Accept-Encoding: gzip` and decompresses 2xx gzip bodies (it strips `Content-Encoding` and `Content-Length` from the wrapped response). Installed in `DeadlockApiConfig.restClientBuilder` (outer), the gate is inside it. Measured on `/v1/assets/ranks`: 37,220 B to 1,790 B. Conditional requests (304) and 503-vs-404 disambiguation were evaluated and not done (upstream answers 503 for unknown matches, indistinguishable from Steam busy).
- **Coach `aim_mechanics` (045):** key `aim_mechanics`, only for heroes 13, 25, 58, 80, 84 (Silver 80 has N=4 and an inconclusive calibration; the owner chose to include it). Uses the final snapshot: `accuracy_pct` = shots_hit / (hit + missed), `shots`, `crit_pct` (only with 250+ hero bullets hit). `major`: accuracy < 32.0 with 1000+ shots; `notable`: accuracy < 48.0 with 500+ shots; crit rate never changes significance. `SnapshotDetail.heroBulletsHit/heroBulletsHitCrit` are nullable (absent = null; the raw fallback leaves them null). Meaning of shot counting (pellets, post-death hits) is unverified.
- **`/analyze` embed v2 (047):** field order Biggest Leak, Next Game Focus, Key Strength, Key Numbers (aligned monospace table `metric | yours | reference`), Final Build, chart, footer; emoji field names; title/description/footer capped. Chart (`ChartRenderer`, 900x720): reading hints, phase bands (720 s / 1200 s, copied constants), death markers (`ChartData.playerDeathTimesS`), direct labels, final lead annotation. Palette: gold `0xFFC83D` you, grey teammates, blue/orange sides, red deaths (shared with 049). Manual Discord check (desktop and mobile) pending.
- **Persisted analysis input (048):** V5 adds nullable `match_analysis.input_json` (the exact `AnalysisInput` sent to the model, capped at 20,000 chars, null if larger; degraded analyses are not stored). Old rows are null and the report renders as before. `ReportService` parses it tolerantly and the report page shows match overview, metrics vs peers (verdict helper `computeVerdict`) and coach sections in the order phases, deaths, objectives, aim_mechanics, build, recent_form, matchup. CSP and headers unchanged, no JavaScript. Per-death times are not persisted (only coach aggregates).
- **Prompt v3 (046) + aim (045):** `analysis-system.txt` is 5,107 chars; `AnalysisPromptTest` cap is now 5,500 (about 390 left). `focus_area` values: phases, deaths, objectives, build, recent_form, matchup, metrics (schema derives from `AnalysisResult.FOCUS_AREAS`). `biggest_leak` tie-break: deaths, phases, objectives, aim_mechanics, build, matchup, recent_form; `aim_mechanics` is also a `focus_area` value. `ttk_*` are context only (never a leak by themselves, never "ambush"). Pending: live `/analyze` to confirm Anthropic accepts the longer enum and the model does not call ttk an ambush.
- **Coach `deaths` time-to-kill (044):** optional fields `ttk_median_s`, `ttk_p90_s`, `ttk_counted` on `DeathsPayload`, from `DeathEvent.timeToKillS`. A value is valid if finite, `> 0` and `<= 60.0` (`TTK_MAX_VALID_S`); `-1.0` (probably "unknown", unconfirmed), null, 0 and outliers are excluded; at least 3 valid values (`MIN_TTK_SAMPLES`) or the fields are omitted. `significance` is unchanged and **no ambush threshold exists**: on 10 samples (744 deaths) only 1.2% of values are below 2.5 s and the data supports no cut; the meaning of `time_to_kill_s` is unconfirmed. Calibrate on a larger sample before any threshold. Explained in the prompt since 046.
- **Coach `objectives` (043):** key `objectives`; `MatchTelemetry.midBoss` (`List<MidBossEvent>`, null on the raw fallback) and `PlayerTelemetry.bossDamage` (final cumulative, JSON adapter only). `major`: enemy claimed 2+ Mid Bosses or stole the Rejuvenator; `notable`: loss with an enemy claim, steal by our team, or our claim with 25%+ team boss damage share. Explained in the prompt and added to the `focus_area` enum since 046. `mitigation` is deferred: no calibration, only 10 matches. `target_focus` was dropped: the earlier signal came from a denominator bug; corrected, carry focus does not differ between winners and losers (d = -0.05, N = 516).
- **Concurrency (041):** JDA events run on a virtual-thread pool. All deadlock-api requests pass `DeadlockApiGate` (fair semaphore, `deadlock-api.gate.max-concurrent` default 1, `acquire-timeout` 20 s; a timeout is an `IOException` mapped to the usual unavailable error). Per-user event ordering is no longer guaranteed (`/link` then `/analyze` at the same instant may say not linked). Web server threads are still platform threads.
- **Performance (039):** chart rendered in memory; `spring.jpa.open-in-view: false`. Owner decisions still open: skip `getPlayerRank` for ranked matches, `spring.threads.virtual.enabled`, V5 indexes (not needed below ~50k accounts). Any new cache must be added to `DeadlockApiClientCachingTest.cacheTtlsAndSizesMatchTheDesign` (exact set of names, TTLs, sizes); parallel tasks conflict there, resolve by keeping all entries.
- **Report page (049):** `/r/{publicId}` has a hero banner, verdict strip, key numbers with CSS bar classes `w0..w100` (no inline `style=`), a charts block, collapsible `<details>` (metrics table first and open, coach sections, other signals), final build and footer; light/dark and print styles. Charts are server-rendered SVG from `ReportChartsSvg` (and `SoulCurveSvg`) at `GET /r/{id}/soul-lead.svg` (alias `lead.svg`), `phases.svg`, `deaths.svg`, `metrics.svg`, plus the existing `soul-curve.svg` and PNG; all text and alt texts come from `report.chart.*`/`report.curve.*` keys (numbers pre-formatted as strings). Palette shared with 047: gold you, grey benchmark, blue/orange teams, green/red verdicts. The deaths chart shows the three phase counts only (per-death times are not stored). CSP and headers unchanged, no JavaScript. Manual browser checks (desktop, 360 px mobile, dark mode, print) are **not done**.
- **Flyway:** V1 `linked_account`, V2 `match_analysis`, V3 `analysis_usage` (dropped by V6), V4 `match_analysis.public_id`, V5 `match_analysis.input_json`, V6 drops `analysis_usage`. Next is V7; check open branches for a clashing number.

## Deadlock API facts (observed in real responses)
- Host `https://api.deadlock-api.com`. Analytics limit 200 req/min per IP; 503 with `Retry-After` under load; never fire parallel uncached analytics calls.
- `match-history`: array newest first, 200 entries kept; `[]` for accounts without data; `player_match_outcome` 0 before ~2026-07-30; win = `match_result == player_team` (inference); `ranked_display_badge` non-null only for ranked, 80% of one account's recent 200 matches.
- `player-stats/metrics`: filters `hero_ids`, `min/max_average_badge`; keys `percentile25/50/75`; no benchmark for net worth at 10/20 min or item timing (use the performance curve and `item-stats` `avg_buy_time_s`).
- `matches/{id}/metadata`: JSON in `match_info`, 12 players; per player `hero_id`, `team`, `player_slot`, `assigned_lane` (values 1, 4, 6 seen, 2 players per team per lane), `death_details[]` (`game_time_s`, `killer_player_slot`, `time_to_kill_s`, `death_duration_s`, positions), `items`, `stats[]` snapshots at 180, 360, 540, 720, 900, 1200, 1500, 1800, 2100 s plus final (net worth, damage, healing, creep kills, possible creeps, shots, damage taken, gold sources), `power_up_buffs` (since 2026-09-29). Also `damage_matrix`, `objectives`, `mid_boss` (shape not inspected). May return 503 "Steam is busy"; a non-existent match returns 503, not 404. `item_id` is unsigned 32-bit (use `long`). `player-performance-curve` and `hero-counter-stats` (42 rows for hero 31) confirmed in `docs/evidence/029-coaching-analytics/` (local only, not committed: contains real account data).
- `players/{id}/rank`: zeros for unranked. `players/steam?account_ids=` returns 200 `[]` for unknown ids. Ranks tiers 0-11; `/v1/assets/items` is ~8 MB.

## Known limitations and risks
- No per-user cooldown, no budget cap and no cap on concurrent Anthropic calls: since 051 the owner pays all AI cost and only deadlock-api and Anthropic rate limits bound it (a cooldown or cap is a separate task). With gate `max-concurrent=1` a burst of cold analyses queues up to 20 s, then fails as unavailable.
- `/analyze` quality (audit of 4 real analyses): numbers are grounded, but reasoning errors (compares a value with the wrong median), "leaks" in dominant games (0 denies) and no priority by impact. Coach upgrade built (031-035 data layers, 037 prompt/schema v2) but **not yet judged with real analyses**; 010 (tuning with testers) is pending. `max_tokens` is 1500 (raise in 037 if needed).
- `/analyze` with duration <= 0 throws `IllegalArgumentException` (generic error). Re-linking to another account keeps the old account's stored analyses. `/leaderboard server` considers only the 500 most recently linked accounts.
- Web report: `rank` and `result` not stored; the page needs the cached metadata (24 h) for duration/build/chart and degrades without it.
- Fonts for the chart are installed in the Docker image (task 036) but a real container render check on the server is still pending; a render failure only drops the image.
- First emoji sync uploads ~315 application emojis (1-3 min); `MarkdownSanitizer` does not neutralize `@everyone` (embeds do not ping); private profiles without `personaname` unverified.
- Data coverage gaps in deadlock-api; match metadata can be unavailable (degraded mode: history metrics only). Death positions have no map-zone data (do not claim "died in enemy territory").
